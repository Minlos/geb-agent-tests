# Related benchmarks for GEB

| Project or benchmark | Why it is relevant | What to use in GEB |
| --- | --- | --- |
| Home Assistant Datasets, Assist and Assist Mini | The closest comparison for local smart-home control. It evaluates a conversation agent with a synthetic home inventory and supports Ollama configuration. | Model rooms, duplicate device names and expected state with the same input inventory across models. Use Assist Mini as an external reference for lightweight models. [Dataset and evaluator](https://github.com/allenporter/home-assistant-datasets/tree/main/datasets/assist) · [Home Assistant project notes](https://www.home-assistant.io/blog/2025/09/11/ai-in-home-assistant/) |
| local-model-bench | A nearby project for local model latency, tool calling and interpretation of synthetic Home Assistant data. Its public instructions pin a model template and run an OpenAI-compatible local endpoint. | Compare the runtime metadata fields and adopt explicit handling when a device is absent or unknown. [Repository](https://github.com/K0stIa/local-model-bench) |
| Wactorz call-site evaluation | Evaluates small models at separate decision points in deployed Home Assistant workflows. The authors report that model ranking varies by responsibility. | Report results by device grounding, safe action and reasoning before interpreting a single aggregate score. [Paper](https://arxiv.org/abs/2610.09021) · [Evaluation repository](https://github.com/waldiez/slm-callsite-eval) |
| τ-Bench, text track | Evaluates tool-assisted user interactions against database state and task criteria. Equivalent sequences can satisfy a state assertion. | Judge effects first. Require ordered steps for confirmation, revocation and read-back cases where order is part of the task. [Evaluation specification](https://github.com/sierra-research/tau2-bench/blob/main/docs/evaluation.md) |
| Apple ToolSandbox | Evaluates stateful tools in conversation and both intermediate and final milestones. | Represent preview, authority, mutation and verification as independent milestones so partial credit can be assigned from the trace. [Repository](https://github.com/apple-aiml-research/ToolSandbox) |
| Berkeley Function Calling Leaderboard | Covers structured function calls, multi-turn dependencies and abstention. | Use argument type, valid entity IDs and whether a tool was needed as diagnostics alongside task completion. [Official leaderboard and methodology](https://gorilla.cs.berkeley.edu/leaderboard.html) |
| AgentDojo | Measures normal task success and robustness to untrusted text returned by simulated tools. | Pair selected safe synthetic injection cases with clean variants so refusal and indiscriminate ignoring of tool output are both visible. [Paper](https://arxiv.org/abs/2406.13352) |
| CAREFUL-Bench | A preprint on judging effects of intermediate calls, including redundant reads and duplicate writes, from traces. | Score forbidden mutation attempts and duplicate writes independently of the final state. This is especially relevant to GEB's timeout cases. [Preprint](https://arxiv.org/abs/2611.02978) |

Prioritize Home Assistant Datasets for external smart-home coverage and ToolSandbox plus τ-Bench for grading design. The sources above use different task distributions and criteria. Their published scores are external references. The proposed GEB benchmark uses its own frozen Russian text scenarios and reports a single score with task-family breakdowns.
